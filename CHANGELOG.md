# Changelog

## Unreleased

### Changed
- Collectors are now configured entirely from the panel. The collector registers with an empty app list and the panel pushes the stored `CollectorConfig` (JSON) over the live WebSocket; the collector hot-reloads on receipt via the supervisor. The shared config type (`types.CollectorConfig`) owns validation and app mutation (`AddApp` / `AddUptimeApp` / `RemoveApp`) used by both the panel and collector, and the panel and collector reuse the shared source/health/lifecycle spec types instead of duplicating them. The `tracer-collector add` CLI and local app config in `collector.yaml` are gone; the collector config now holds only the sender section (api key, panel host, name). Apps and uptime monitors are added from the panel UI by service name, with the log format auto-detected by the collector's format guesser and returned over the WebSocket.
- The log detail page exports clean semantic markdown (`Accept: text/markdown`): a back link to the log group, the message as an `h1` heading, one `Time:`/`Level:`/`Trace ID:` line under `## Metadata`, and one `key: value` line per context entry under `## Context`. The markdown middleware drops any element carrying a new `markdown-exclude` attribute before conversion, so page chrome (site nav, since filter) never reaches agents; the LLM docs describe the attribute. Shared `BackwardAnchor`/`ForwardAnchor` components render the `<`/`>` arrows inside `markdown-exclude` spans (used by all back links and the Metrics links), and absent values (empty trace ID, empty context values) render as `-` instead of nothing.
- The panel root (`/`) now serves the LLM docs as a starting prompt: authenticated callers are redirected to `/panel/` as before, while unauthenticated callers keep the login redirect but the response body carries the redirect anchor (as `http.Redirect` writes it) plus the LLM docs page rendered from the shared `.templ` source. Agents pointed at the root with `Accept: text/markdown` get the docs converted to markdown by the Accept middleware (including the `[See Other](/auth/login)` anchor so the prompt is self-guiding), so the key's usage is discoverable without following the redirect. The `.md`-suffix routing convention has been removed in favor of the existing `Accept: text/markdown` header: user API keys now authenticate any route uniformly (not just `.md`-suffixed ones), the `/llm` endpoint renders HTML directly (the markdown conversion stays in the middleware), and the docs/templates point at plain routes (e.g. `/panel`) with the markdown `Accept` header set in curl examples.
- The "Metrics" link on the dashboard and collector overview is now a real anchor (`href`) instead of an htmx navigation link (`hx-get` + `hx-target="body"` + `hx-push-url`). The navigation now relies on the browser's native navigation, so middle-click, ctrl/cmd-click, right-click "open in new tab", and "copy link address" all work, and screen readers / non-JS clients see a proper destination. The "since" filter is cookie-based (not a form field), so the HTML anchor loses nothing. Markdown responses (`Accept: text/markdown`) keep the link without needing the hx-get→href rewrite in the markdown middleware.
- Creating a notifier, a user, a user API key, or a collector API key now navigates to the created entity's detail page instead of staying on the settings page: the notifier create flow redirects to `/settings/notifiers/{id}` (where subscriptions are managed), the user create flow redirects to `/settings/users/{id}` (where app permissions are managed), and both API-key create flows redirect to their detail page (`/settings/api-keys/{id}` and `/settings/admin/collector-api-keys/{id}`) with the htmx `HX-Redirect` header. The create services return the new record (with the plaintext, shown only once) as a single result (`GeneratedCollectorAPIKey`/`GeneratedUserAPIKey`), so handlers no longer look the id up or juggle three return values. Both detail pages show the entity's data plus the shared scope-tree form for enabled collectors/apps, all disabled by default.
- The notifier detail page's app list is built by the notify service (`GetSubscriptionOptions`) instead of the settings handler: the service owns collector/app listing, access filtering, and subscription marking, and returns `[]domain.ScopeEntry` straight to the views — no intermediate view DTOs or per-view grouping helpers. `ScopeTree` is the only view type shared by both the notifier and user surfaces; `ScopeEntry` lives in `domain` (with the shared `SanitizeID`) so neither view declares its own permission type.
- `notify.Service.List` returns service types (`[]notify.Setup`) instead of raw `db.Notifier` rows, so the DB entity never crosses the service API boundary

- The panel no longer has read-only mode. The `-readonly` flag, its middleware, and the `web.NewServer`/settings plumbing are gone; the panel inside the container is always writable. Read-only enforcement for a demo/exposed panel now lives in the nginx reverse proxy that fronts it (see `e2e/`), which rejects non-GET requests except the session routes (`/auth/*`) — so a read-only demo still allows login and browsing, while state-changing actions such as reveal/delete by POST are blocked at the proxy.
- App cards on the collector overview no longer carry "Settings" or "Delete" actions — they are plain links to the app's detail page. The detail page moves those actions into its own header (back link, Settings, Delete), and deleting an app from there redirects back to the collector overview via the htmx `HX-Redirect` header instead of re-rendering the grid.

### Added
- User API keys on the Settings page now behave like collector API keys: each row links to a detail page (`/settings/api-keys/{id}`) where the plaintext key can be revealed with the eye button and the key can be deleted from the page instead of from the table row. Keys are stored encrypted (new `key_encrypted` column) so the plaintext can be shown again; keys created before the migration show "Not revealable".
- The masked key suffix display is gone: since keys are revealable, the `****suffix` hint was redundant. The settings tables now show a plain "View" link per key, the detail pages show a fixed mask until revealed, and the `key_suffix` column was dropped from both key tables (migration `00005_drop_key_suffix.sql`). Collector API keys also gained an integer `id` primary key — they are now addressed by id (`/settings/admin/collector-api-keys/{id}`) like user API keys, and `GetCollectorAPIKeyByName` / `GetCollectorAPIKeyDisplay` / `maskedAPIKeySuffix` were removed in favor of `GetCollectorAPIKeyByID`.
- Every panel HTML page is now available in markdown: a request with an explicit `Accept: text/markdown` header (with a q-value at least as high as `text/html`) gets the rendered HTML converted to markdown on the fly by a proxied-response-writer middleware, while `*/*` and browser defaults stay HTML. HX-get placeholders (apps grid, stats, log groups, log entries) are converted to links to their fragment routes, so the markdown keeps the dynamic routes as anchors instead of dropping the empty placeholders. Streaming responses (the topology SSE feed) and non-HTML responses (JSON, static assets, API keys) pass through unconverted. Markdown is selected purely by the `Accept` header; the former `.md`-suffix convention has been removed.
- The panel's client-side scripts are now external files under `/static` (navbar/since, markdown checkbox, scope tree, collector stats charts, topology graph) instead of inline `<script>` blocks, and static assets are served with `Cache-Control: public, max-age=3600` so browsers cache them and revalidate instead of re-downloading on every page load.
- The panel now serves a favicon: a generated SVG mark with the project's topology motif (a central "collector" panel node ringed by six surrounding nodes on mathematically precise polar coordinates — five fanned evenly across the top arc at 150°, 120°, 90°, 60° and 30° labelled "app", one at 270° below labelled "panel" — connected by curved bezier edges on a charcoal background) plus a PNG `apple-touch-icon` for touch devices, both registered in the shared page head. Every coordinate is derived from a set of geometry constants by `scripts/gen-favicon`: the leaf centers are computed on a shared reference circle (so they line up precisely) and each bezier edge's control point is derived from the segment midpoint, then the SVG is emitted from that model by `make favicon` rather than hand-written.

### Fixed
- The reconnecting sender no longer dials after Close, and `TestReconnectingCloseDuringFactory` no longer panics when the actor retries the factory (`close of closed channel`).
- Saving an app from the add/edit form no longer drops the log source when a health-check URL is set. Create and update persist any valid combination — logs only, uptime only, or both — and adding a URL to an existing log-collecting app keeps journalctl/kubectl/file collection running.
- The log groups section on the app page no longer renders a skeleton: the lazy placeholder keeps only the static "Log Groups" heading (no pulsing bars over the heading, level filters, or table headers) and the real template loads with the fragment, since the section sits at the end of the page. The skeleton rules were added to AGENTS.md: never cover static text with skeletons, always reuse the real template for a skeleton, and never add skeletons to content at the end of the page.
- Notifier subscriptions and user app access now render as a hierarchical markdown-style scope tree (`[x]`/`[ ]` collector rows with indented app rows) shared by both surfaces, instead of the browser checkbox grid. Unchecked rows submit nothing, so by default no subscription or access is enabled — previously `checked={bool}` rendered as `checked="false"` (which browsers treat as present) so every checkbox appeared checked and saving enabled everything. The tree's collector row toggles all its apps, and the checkbox/scope scripts are idempotent so htmx fragment swaps do not double-wire toggles. The shared `ScopeTree` accepts a flat list of collector/app entries and groups them by collector internally, matching the original pre-templ markdown-checkbox design (helper text, "No applications available yet." empty state, bordered Save Changes / Cancel row). The user detail page (`/settings/users/{id}`) is now a full page mirroring the notifier detail page — back link, header with delete, info grid, and the shared scope tree — instead of a bare fragment.
- `tracer-panel -init -force` no longer logs everyone out when the admin password has not actually changed: `ResetPassword` detects an unchanged password and skips the password write and session purge (the user is still promoted to admin). Previously every container restart re-hashed the same password and deleted all admin sessions, forcing a re-login. The no-op only applies when the password is stable across boots — set `TRACER_ADMIN_PASSWORD` in the container environment so `-init -force` resets to the same value each time; without it, `-init` still generates a fresh random password every boot and the full reset (with session purge) runs
- `tracer-collector -help` now prints the complete CLI interface — global flags, every subcommand, and each command's flags — instead of only the three global flags. `tracer-collector <command> -help` shows a command's usage, `tracer-collector help` is an alias for the top-level help, and both work even when the collector is not yet configured (previously `add -help`/`set -help` failed on the missing config or a privilege check before the flag parser ran)
- `tracer-collector kubectl-setup` now also points every existing kubectl source that does not already set a `kubeconfig` at the installed `/etc/tracer/kubeconfig`, so a kubectl source can never silently fall back to an unreadable system default and fail with `SOURCE_ERROR[source_read_failure]: kubectl logs (...) exited: ... permission denied`
- The kubectl source inherits the parent environment when setting `KUBECONFIG` (previously `cmd.Env` was replaced entirely, dropping `PATH`/`HOME` for the kubectl process)
- The collector no longer emits `SOURCE_ERROR[parse_error]` entries for unparseable lines (e.g. `parse failed: invalid character 'ð' looking for beginning of value` from mixed-format or binary lines in a kubectl container-log stream). Such lines are logged locally in the collector journal at error level — a missed log entry is a critical loss of observability data — with the truncated offending line, and dropped, so tracer's own diagnostics never appear in the panel next to real application logs
- The Forgejo notifier's API token input on the Settings page now uses a compact placeholder (`r:user, r:org, r:repo, w:issue`) instead of the full scope names, and the input width was narrowed back to match the other credential fields so the hint is not truncated on narrow screens
- `tracer-collector add` with an inline-equals value flag (`--favour=type:json`) no longer mis-consumes the following token, and `tracer-collector set <key> -h` sets the value `-h` instead of printing help (help detection now mirrors how each command's flag parser actually behaves)
- Collector kubectl sources no longer pass `--prefix=true`, so `kubectl logs` emits raw container log lines. The `[pod/<pod>/<container>]` prefix was merged into the first key by the slog text tokenizer (e.g. `[pod/x/y] time=...`), which broke both `tracer-collector add` format guessing ("missing required field(s): timestamp") and runtime parsing of JSON/slog text logs
- `tracer-collector add` no longer hangs when sampling a file source: a seek switches the file source into a bounded historical read that returns `io.EOF` once drained (the daemon's follow behavior is unchanged since it never seeks), and the sampler falls back to the start of the log when the tail seek lands past every complete line
- The notifier detail page (`/settings/notifiers/{id}`) now renders the app subscription checkboxes and Save button. Previously the page embedded the subscriptions form but never populated the app list, so it always showed "No apps available.". Subscriptions are managed on the detail page only: the standalone `/settings/notifiers/{id}/subscriptions` page was removed, and the dead `NotifierListView` component (the only place a "Subscriptions" link existed) was deleted
- App-page loading skeletons (stats cards, log groups table, apps grid) gained proper breathing room: the placeholder bars now mirror the real components' spacing utilities exactly, so the swap-in never shifts the page height
- `tracer-collector add` prompts are only shown on a real terminal (an `isatty` check replaces the character-device heuristic, which treated `/dev/null` as interactive)
- `tracer-collector add` flags now work before or after the source argument (Go's flag parser stops at the first positional, so previously `add myapp --no-confirm` silently ignored the flag); unexpected trailing arguments are rejected instead of silently dropped
- Collector kubectl and journalctl sources no longer report `SOURCE_ERROR[source_read_failure]: EOF` for a failing external process: stderr and the exit status are now captured, so the panel log shows the real reason (e.g. `error loading config file ...: permission denied`) instead of a bare `EOF`. A clean stream end (exit 0) is still `io.EOF`
- The collector no longer emits `source_read_failure` error events for a clean end of stream: `io.EOF` from a source is treated as a silent retry (with backoff) instead of an error, so a kubectl/journalctl process that exits 0 no longer spams the panel every few seconds

### Added
- New `forgejo` notifier type: tracer-panel creates an issue in a Forgejo repository via its API (`POST /api/v1/repos/{owner}/{repo}/issues`) for the first `error`-level entry of each new log group. Configuration (base URL, API token, owner, repo) lives in Settings → Notifications on the new Forgejo tab; which collector/app pairs trigger issues is chosen with the same checkbox grid used for user access and notifier subscriptions. The created issue's number and URL are recorded on the log group; a connection check (not a test issue) validates the token when the notifier is saved, and the app/collector access policy of the notifier's owner applies. The forgejo setup form gains a staged "Verify & load" flow: the button is enabled once the base URL and API token are filled in, and clicking it validates the token and loads the available owners (the token's user plus its organizations) into an owner autocomplete; picking an owner loads that owner's repositories (user repos first, falling back to organization repos) into a repository autocomplete; picking a repository validates it and loads its labels (multi-select) and open milestones (single select) into the form — the selects stay disabled with a "set credentials and repository" placeholder until then, show a disabled "Loaded (N)" first option when options exist, and "None" when the repo has none. Selected labels/milestones are applied to every created issue. The entry that creates a new error group emits a `new_error_group` notification instead of the usual per-entry alert (later entries alert normally), and notifications now carry a typed payload (a `LogEntry` for log-derived events, a string otherwise) that each notifier renders into its own presentation instead of a dispatcher-assembled message
- Panel pages with time-varying data now auto-refresh every 15s using htmx's native `every` polling trigger: dashboard and collector overview (collector stats row + apps grid), app analytics (uptime, stats cards, log groups), and log group details (count/first/latest metadata). The collector stats row is served as a pollable fragment at `/panel/collectors/{collector}/stats` (always showing the Metrics link into resource history on both the dashboard and the collector overview — the overview's header `[resources]` link was removed as redundant), the app uptime panel at `/panel/collectors/{collector}/apps/{app}/uptime`, and the log group metadata at `/panel/collectors/{collector}/apps/{app}/logs/groups/{groupID}/summary`. The summary fragment carries a backend-set `since` timestamp; when new rows arrive after it, a `+N` badge with a "There are new log records, refresh the page to see them" tooltip is shown. The bundled htmx was bumped 2.0.0 → 2.0.7 (the polling code relied on `outerHTML` swap cleanup that 2.0.4+ guards against a detached target)
- The apps grid now bakes each app's uptime and error count into the grid response (with the same red/yellow/gray health color-coding the per-app fragments applied), so polling it costs one request instead of a 2×apps fan-out; per-app stats are read concurrently across the per-app databases. The per-app fragment routes `GET .../apps/{app}/uptime/percentage` and `GET .../apps/{app}/errors/count` were removed with their handlers/templates (the uptime percentage is still served for the app analytics page at `GET .../apps/{app}/uptime`)
- `tracer-collector kubectl-setup` installs a kubeconfig at `/etc/tracer/kubeconfig` (root-owned, readable by the `tracer` group) so kubectl sources work for the collector service user, which has no home directory; it verifies the source config, copies it, verifies the copy, and wires the installed file into every existing kubectl source. `--kubeconfig <path>` overrides auto-detection (`$KUBECONFIG`, `~/.kube/config`, k3s/kubeadm locations)
- `tracer-collector add` for kubectl sources now installs the kubeconfig automatically (`--kubeconfig <path>` to override auto-detection), sets the `kubeconfig` param on the source, and fails if the installed config cannot read the resource — with a pointer to `kubectl-setup`
- `tracer-collector add` now offers follow-up actions when format guessing fails on missing fields: it lists every key present in the offending line (carried by the guesser's `MissingFieldsError`), and on a terminal interactively maps each missing field to a chosen key, retrying with the resulting `--favour`. Missing optional fields (e.g. `trace_id`) are also reported and prompted, but can be ignored with Enter instead of mapped
- `--favour` can now supply a field mapping for fields the guesser cannot find at all (previously it only resolved conflicts between lines); the mapped key must exist in the log line. This includes optional fields: mapping `trace_id_field` to a non-synonym key works
- `tracer-panel -init -force` overwrites the password of the given admin user when the panel is already initialized and exits 0 instead of 2 (existing sessions are invalidated, missing user is created as admin)
- Collector API key detail page: reveal the full key with an eye icon (POST-backed, so it is rejected by the read-only middleware — keys can never be exposed in read-only mode)
- Collector API key plaintext is now encrypted at rest (AES-256-GCM) with a master key in `{dataDir}/keys.key` (0600) or `TRACER_KEY_SECRET` env var; keys created before this version have no stored plaintext and show "Not revealable"
