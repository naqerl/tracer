# Refactor Plan: Domain-First Project Structure

## Objective
Refactor into strict domains (`collector`, `panel`, `landing`, `shared`) and keep repository root minimal. Anything used only by one domain must live inside that domain.

## Hard Requirements
1. Root directory remains clean and contains only top-level meta/build files.
2. `sql`, `sqlc`, and generated `db` code are panel-only and must move under panel domain.
3. No cross-domain imports except through `libs/shared`.
4. Collector and landing must not depend on panel internals.

## Root Cleanliness Rules
Allowed at root:
1. `go.mod`, `go.sum`
2. top-level `Makefile`
3. `.github/`, `.gitignore`
4. `README.md`, `CHANGELOG.md`
5. `apps/`, `libs/`, `scripts/`, `docs/`, `demo/`, `deploy/`

Must move out of root:
1. `cmd/*` -> `apps/*/cmd/*`
2. `config/*` -> owning app domain
3. `core/services/*` -> owning app or `libs/shared`
4. `web/*` -> `apps/panel` or `apps/landing`
5. `sql/*`, `sqlc.yaml`, `db/*` -> `apps/panel/*`

## Ownership Matrix
1. Collector-owned: watcher, log parsing, ws client, stats agent, collector config.
2. Panel-owned: API ingest, auth/session, notifier stack, collector registry, retention, all database lifecycle and queries.
3. Landing-owned: landing pages and docs-like public pages.
4. Shared-only: generic middleware/helpers/types with no business coupling.

## Implementation Plan
1. Add architecture rules doc (`docs/architecture.md`) with ownership matrix and import constraints.
2. Create new domain folders (`apps/collector`, `apps/panel`, `apps/landing`, `libs/shared`) with empty bootstrap packages.
3. Move panel DB assets first:
4. Move `sql/*` to `apps/panel/sql/*`.
5. Move `sqlc.yaml` to `apps/panel/sqlc.yaml`.
6. Move generated `db/*` to `apps/panel/db/*`.
7. Update SQLC generation target to run from `apps/panel` path.
8. Refactor panel code imports to `apps/panel/db` and `apps/panel/sql/*` embed packages.
9. Move panel entrypoint from `cmd/panel` to `apps/panel/cmd/tracer-panel`.
10. Move panel web/routes from `web/*` and panel parts of `core/services/*` into `apps/panel/internal/*`.
11. Move landing handlers/templates to `apps/landing/*`; keep optional embedded compatibility in panel via adapter only.
12. Move collector entrypoint from `cmd/collector` to `apps/collector/cmd/tracer-collector`.
13. Move collector-specific services from `core/services/*` into `apps/collector/internal/*`.
14. Extract true shared utilities into `libs/shared/*`; avoid moving domain logic there.
15. Add import-boundary check script (`scripts/check_boundaries.sh`) to fail forbidden imports.
16. Update root Makefile:
17. Build targets point to `apps/*/cmd/*`.
18. SQLC target points to `apps/panel/sqlc.yaml`.
19. Add `build-landing` and release targets for all binaries.
20. Update CI workflow to build/test by domain and publish 3 binaries.
21. Update demo and deploy scripts to new binary paths and optional landing service.
22. Delete deprecated directories only after all imports and CI are green.
23. Final pass: enforce no root business code outside domain folders.

## PR Phases
1. Phase A: scaffolding + rules + boundary checks.
2. Phase B: panel DB move (`sql/sqlc/db`) and import rewiring.
3. Phase C: panel app move (routes/services/entrypoint).
4. Phase D: collector app move (services/entrypoint).
5. Phase E: landing app move + standalone binary.
6. Phase F: CI/demo/deploy updates + cleanup of old paths.

## Acceptance Criteria
1. Root has no domain business code outside `apps/` and `libs/`.
2. SQL migrations, SQLC config, and generated DB code exist only in `apps/panel/`.
3. Collector compiles and runs without importing panel packages.
4. Landing compiles and runs without importing panel packages.
5. `go test ./...`, `make vet`, and panel SQL generation pass.
6. Demo works after clean reset (`make -C demo clean-volumes up`).

## Risks and Controls
1. Import cycles while moving packages: mitigate with boundary checks in every PR.
2. Path churn breaking CI/scripts: update make/workflows in same PR as each move.
3. SQL generation drift: regenerate SQLC and compile-check immediately after panel DB move.
4. Hidden panel coupling in shared: reject any shared package importing app domain code.

## Handoff Note
Execution agent should prioritize Phase B first (panel DB ownership), since it enforces the core requirement that SQL/DB/sqlc are panel-only.
